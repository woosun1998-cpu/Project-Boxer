# Git 기초 + Cursor 소스제어(Ctrl+Shift+G) 정리

## 1) 왜 Git을 쓰는가?

Git은 코드 변경 이력을 저장하는 도구입니다.

- 언제 무엇을 바꿨는지 기록
- 실수했을 때 이전 상태로 복구
- 팀원과 안전하게 협업
- 기능별 브랜치로 작업 분리

---

## 2) 핵심 개념 3가지: 스테이징 / 커밋 / 푸시

## 2-1. 스테이징(Staging)

**의미:**  
이번 커밋에 넣을 파일을 고르는 단계

- 수정된 파일 전체를 무조건 커밋하지 않음
- 필요한 파일만 선택해서 스테이징 가능

명령어:
```bash
git add 파일명
git add .
```

확인:
```bash
git status
```

---

## 2-2. 커밋(Commit)

**의미:**  
스테이징된 변경사항을 로컬 저장소에 "스냅샷"으로 기록

- 커밋은 내 PC(로컬)에만 저장됨
- 아직 GitHub에는 올라가지 않음

명령어:
```bash
git commit -m "로그인 버튼 스타일 수정"
```

좋은 커밋 메시지 예시:
- `fix: 로그인 실패 메시지 표시 개선`
- `feat: 대시보드 빠른 이동 버튼 추가`
- `docs: 실행 가이드 문서 정리`

---

## 2-3. 푸시(Push)

**의미:**  
로컬 커밋을 원격 저장소(GitHub)에 업로드

명령어:
```bash
git push origin 브랜치명
```

예시:
```bash
git push origin boxer/donghyeon
```

---

## 3) 전체 작업 흐름(가장 자주 쓰는 순서)

```bash
git status
git add .
git commit -m "작업 내용 요약"
git push origin 내브랜치명
```

---

## 4) Cursor 소스제어(Ctrl+Shift+G) 상세 설명

`Ctrl + Shift + G`를 누르면 왼쪽에 **Source Control(소스제어)** 패널이 열립니다.

## 4-1. 패널에서 주로 보이는 항목

- **CHANGES**: 수정했지만 아직 스테이징하지 않은 파일 목록
- **STAGED CHANGES**: 스테이징된 파일 목록
- **커밋 메시지 입력칸**: 커밋 설명 작성
- **Commit 버튼**: 스테이징된 파일 커밋
- **Sync/Push/Pull 버튼**: 원격 저장소와 동기화

---

## 4-2. 파일별 아이콘/상태 의미

- `M` (Modified): 기존 파일 수정됨
- `A` (Added): 새 파일 추가됨
- `D` (Deleted): 파일 삭제됨
- `U` (Untracked): Git이 아직 추적하지 않는 새 파일
- `UU` (Conflict): 병합 충돌 발생 파일

---

## 4-3. 소스제어에서 스테이징하는 방법

방법:
1. `CHANGES`에서 파일 옆 `+` 클릭 → 해당 파일만 스테이징
2. 섹션 제목 옆 `+` 클릭 → 전체 스테이징

스테이징 취소:
- `STAGED CHANGES`의 파일 옆 `-` 클릭

---

## 4-4. 소스제어에서 커밋하는 방법

1. 필요한 파일 스테이징
2. 커밋 메시지 입력
3. `Commit` 클릭

주의:
- 스테이징된 파일이 없으면 커밋이 안 됨
- 메시지를 비우면 커밋 실패할 수 있음

---

## 4-5. 소스제어에서 푸시/풀 하는 방법

- **Push**: 내 로컬 커밋을 원격으로 올림
- **Pull**: 원격 변경을 내 로컬로 가져옴
- **Sync**: 보통 Pull + Push를 묶어 처리

초심자 권장:
1. 먼저 `Pull`로 최신 반영
2. 충돌 없으면 작업 커밋
3. 마지막에 `Push`

---

## 4-6. 파일 비교(Diff) 보는 방법

- `CHANGES`에서 파일 클릭하면 변경점 비교 화면 표시
- 왼쪽: 이전 내용
- 오른쪽: 현재 내용
- 색상으로 추가/삭제/수정 라인 확인 가능

---

## 4-7. 충돌(Conflict) 났을 때 소스제어에서 보는 방법

충돌 파일은 보통 `UU` 상태로 보입니다.

파일 열면 충돌 마커가 보일 수 있음:
```text
<<<<<<< HEAD
내 코드
=======
상대 코드
>>>>>>> 브랜치명
```

해결 순서:
1. 원하는 내용으로 수동 수정
2. 충돌 마커 삭제
3. 저장
4. 스테이징
5. 커밋

---

## 5) 자주 하는 실수와 해결

## 5-1. add를 안 해서 커밋에 누락됨
증상:
- 커밋했는데 변경이 안 올라감

해결:
```bash
git add .
git commit -m "누락 파일 추가"
git push origin 브랜치명
```

## 5-2. push 안 해서 GitHub에 안 보임
증상:
- 로컬에서는 커밋 있는데 GitHub엔 없음

해결:
```bash
git push origin 브랜치명
```

## 5-3. 잘못된 파일(.env 등) 올림
해결 순서:
1. `.gitignore`에 추가
2. 추적 제거:
```bash
git rm --cached 파일명
```
3. 커밋/푸시

---

## 6) 최소 안전 수칙(팀 협업용)

- 작업 전 `pull`로 최신 반영
- 기능 단위로 자주 커밋
- 커밋 메시지는 짧고 명확하게
- `main` 직접 작업보다 브랜치 작업 권장
- `.env`, 비밀키, 대용량 개인파일은 업로드 금지

---

## 7) 한 줄 요약

- **스테이징**: 커밋할 파일 선택  
- **커밋**: 선택한 변경을 로컬 기록  
- **푸시**: 로컬 기록을 GitHub로 업로드  
- **Ctrl+Shift+G**: 이 과정을 GUI로 쉽게 관리하는 소스제어 창
